# 007. 같은 clientId의 재전송은 새 응답을 만들지 않는다

## 상황

전송이 실패한 메시지에는 재시도 버튼이 있다. 그런데 "클라이언트는 실패로 봤지만 서버는 이미 받아 처리한" 경우가 있다. 예를 들어 응답 직전에 네트워크가 끊긴 경우다. 이때 재시도하면 같은 질문에 응답이 두 번 생긴다.

## 검토한 대안

1. 재시도할 때 새 clientId를 만든다 — 서버 입장에서는 다른 메시지라서 중복이 생긴다.
2. **재시도는 같은 clientId로 보내고, 서버가 clientId로 턴을 찾는다**

## 결정

2번.

- 완료된 턴이 있으면 같은 `turnId`를 돌려준다. 그 스트림은 `final`만 보낸다.
- 진행 중인 턴이 있으면 `409`
- 없으면 새로 만든다.

클라이언트는 실패한 메시지를 지우지 않고 같은 clientId로 다시 `pending`으로 돌린다.

## 트레이드오프

- 서버가 clientId → 턴 매핑을 보관해야 한다. 목 서버는 메모리에 둔다.
- 서버가 실패로 기록한 턴을 다시 시도하는 정책은 아직 없다. M2의 시나리오에는 서버 측 실패가 없다. `http-5xx`(M4)에서 정한다.
