# 013. 응답을 만들기 전에 실패한 턴은 같은 clientId로 다시 보내면 같은 턴을 다시 쓴다

## 상황

`http-401`, `http-5xx` 시나리오에서는 스트림을 시작하기 전에 실패한다. 이때 사용자 메시지는 이미 `POST /turns`에서 저장된 뒤다. 재시도 버튼은 같은 clientId로 `POST /turns`를 다시 보낸다(decisions/007). 007을 쓸 때는 "서버가 실패로 기록한 턴을 다시 시도하는 정책"이 아직 없었다.

## 검토한 대안

1. 새 턴을 만든다 — 사용자 메시지가 히스토리에 두 번 남는다.
2. `409`로 거부한다 — 사용자는 다시 보낼 방법이 없다.
3. **실패한 턴의 상태를 되돌리고 같은 턴을 다시 쓴다**

## 결정

3번.

- 스트림 시작 전에 실패하면 턴을 `failed`로 기록한다.
- 같은 clientId로 다시 오면 `streaming`으로 되돌리고, 같은 `turnId`와 새 토큰을 준다.
- 장애 시나리오(끊기, HTTP 오류)는 **첫 구독에만** 적용한다. 그래야 재시도와 이어 받기가 성공하는 경로를 시험할 수 있다.

## 트레이드오프

- 응답 생성이 시작된 뒤의 서버 실패(`error` 이벤트)는 다루지 않았다. 생성 중 실패를 다시 시도할 때 부분 응답을 어떻게 할지는 정하지 않았다.
- "첫 구독에만 장애" 규칙 때문에, 같은 장애가 반복되는 상황(재시도해도 계속 401)은 시험하지 않는다.
