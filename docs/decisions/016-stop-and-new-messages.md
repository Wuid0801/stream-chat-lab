# 016. 중지는 서버가 거기까지의 응답을 저장하게 하고, "새 메시지" 버튼은 DOM 속성으로만 바꾼다

## 상황

DEMO_SPEC 3장의 기본 기능 중 두 가지가 M4-3까지 남아 있었다.

- 중지 버튼(진행 중 턴 취소)
- 바닥에서 떨어져 있을 때 "새 메시지 ↓" 버튼

중지는 서버 쪽 의미를 정해야 했다. 지금까지는 클라이언트 쪽 취소(`Turn.abort`)만 있었다. abort는 연결을 끊고 사용자 메시지를 `failed('aborted')`로 남긴다. 그런데 서버는 연결과 무관하게 생성을 끝까지 마친다(decisions/011). 결국 사용자는 "중지"를 눌렀는데 히스토리에는 완성된 응답이 남는다.

## 검토한 대안

| 항목           | 대안                                                            | 판단                                                                                  |
| -------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 중지           | 클라이언트만 끊는다 (`abort`)                                   | 서버는 계속 생성하고 저장한다. 화면과 히스토리가 다르다                               |
|                | 서버가 생성을 멈추고 아무것도 저장하지 않는다                   | 이미 본 부분 응답이 사라진다. "입력 내용이 사라지지 않는다"는 실패 UX 원칙과 어긋난다 |
|                | **서버가 생성을 멈추고 거기까지의 응답을 `stopped`로 저장한다** | 화면과 히스토리가 같다. 부분 응답도 남는다                                            |
| 새 메시지 버튼 | React 상태(`useState`)                                          | 바닥에서 떨어져 있는 동안 토큰마다 상태가 바뀌어 목록 전체가 한 번 더 렌더된다        |
|                | **ref로 `hidden` 속성만 바꾼다**                                | 렌더가 늘지 않는다. React는 처음에만 `hidden`을 넣고 이후로는 건드리지 않는다         |

## 결정

- **중지**
  - `POST /turns/:id/cancel`: 생성 중이면 지금까지 만든 토큰으로 응답을 저장하고(`stopped: true`), `done` → `final`을 보낸다. 생성기가 sleep 중이어도 기다리지 않는다. 깨어난 생성기는 `stopped`를 보고 멈춘다.
  - 이미 완료된 턴이면 그대로 돌려준다.
  - 클라이언트 `Turn.cancel()`: 연결을 닫고 `cancelling` 상태가 된다. 이 상태에서는 늦게 온 토큰, 연결 오류, 이어 받기를 모두 무시한다. 결과는 중지 응답으로 확정한다.
  - 준비 중이면(서버에 턴이 아직 없음) `abort`와 같다.
  - 진행 중에는 입력창의 "보내기" 자리에 "중지"가 보인다. 중지된 응답에는 "중지됨"을 표시한다.
- **새 메시지 버튼**
  - 따라가기가 꺼진 상태(사용자가 위로 올림)에서 아래쪽 내용이 바뀌면 보인다. 위에 과거 페이지만 붙은 경우는 보이지 않는다.
  - 누르면 바닥으로 내리고 따라가기를 다시 켠다. 바닥 근처로 직접 내려와도 숨는다.

## 확인 방법

- 서버 단위
  - 생성 중 중지 → 부분 응답이 `stopped`로 저장되고, 구독자는 거기까지의 토큰과 그 응답의 final을 받는다
  - 깨어난 생성기가 토큰을 더 만들지 않는다
  - 구독 전 중지 → 빈 응답
- 컨트롤러 단위
  - 중지 중 늦은 이벤트·오류 무시
  - 이어 받기 대기 중 중지 → 다시 구독하지 않음
  - 준비 중 중지 → 서버 호출 없음
  - 중지 요청 실패 → `cancel-failed`
- E2E
  - 스트리밍 중 중지 → "중지됨"으로 확정되고 더 늘어나지 않는다
  - 첫 토큰 전 중지
  - 새 메시지 버튼이 보였다가, 누르면 바닥으로 간다

## 트레이드오프

- 클라이언트가 마지막으로 그린 텍스트와 서버가 저장한 부분 응답이 다를 수 있다. 서버가 그사이에 토큰을 더 만들었을 수 있기 때문이다. 확정 시 서버 값으로 바꾼다.
- 중지 요청이 실패하면(`cancel-failed`) 사용자 메시지가 실패로 남는다. 서버에서는 생성이 계속되었을 수 있다. 재시도하면 완료된 턴을 돌려받는다(decisions/007).
- 새 메시지 버튼은 React 바깥에서 DOM을 바꾼다. 같은 요소를 React가 다시 렌더하며 `hidden`을 바꾸지 않도록, JSX의 `hidden` 값은 항상 같게 둔다.
