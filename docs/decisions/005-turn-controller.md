# 005. 턴 하나가 준비 → 스트림 → 서버 확인을 끝까지 소유한다

## 상황

실무에서는 이전 턴의 늦은 이벤트가 새 턴을 오염시키는 문제를 세 층의 가드로 막았다(LEARNING.md 6장, 10장).

- 전송 단계: 동기 예약
- 연결 단계: 세대 번호
- 확정 단계: clientId 스냅샷

가드가 흩어져 있어 "지금 어느 턴의 콜백인가"를 한 곳에서 판단할 수 없었다. 토큰 조회 실패 시 예약이 풀리지 않는 경로도 있었다.

## 검토한 대안

1. 층마다 세대 번호를 둔다 (실무 방식)
2. React 상태(useReducer)에 턴 상태를 모두 넣는다 — 렌더 주기에 묶여 동기 예약이 어렵다.
3. **프레임워크와 무관한 컨트롤러 하나가 세대 번호 하나와 턴 전용 지역 상태를 소유한다**

## 결정

3번. `createTurnController().send(text, clientId)`가 `Turn { clientId, id, status, abort() }`를 돌려준다.

- `send`는 첫 `await` 전에 `active`를 잡는다. 준비, 스트림, 서버 확인 중에는 다음 `send`를 거부한다.
- 턴이 끝나거나(완료·실패·취소) 언마운트로 정리될 때 `end()` 한 곳에서 다음을 모두 한다.
  - 연결 닫기
  - 준비 요청 abort
  - 세대 증가
  - 예약 해제
- 모든 콜백은 `my === generation`일 때만 동작한다.
- `onerror`가 오면 즉시 연결을 닫는다(자동 재연결 차단). 토큰이나 `done`을 받은 적이 있으면 `GET /turns/:id`로 확인한 뒤 성공 또는 실패로 판단한다.

## 트레이드오프

- 턴은 한 번에 하나만 진행한다. 동시 전송은 지원하지 않는다.
- 서버 확인이 끝날 때까지 입력창의 전송이 막힌다. 확인 요청이 오래 걸리면 대기가 길어진다. 타임아웃은 M4에서 다룬다.
- React 바깥 객체라서 상태 변경을 콜백(dispatch)으로 전달해야 한다.
