# 008. 바닥 따라가기: 사용자가 위로 올렸을 때만 끄고, 렌더 시점에 위치를 다시 확인한다

## 상황

스트리밍 중에는 바닥 근처에 있을 때만 아래로 따라간다(LEARNING.md 8장). 처음 구현은 `scroll` 이벤트에서 "바닥과의 거리 ≤ 48px"이면 따라가기를 켜고, 아니면 껐다. 두 가지 문제가 나왔다.

1. 새 메시지를 smooth로 내리는 동안에는 거리가 잠시 48px보다 멀어진다. 그 순간의 `scroll` 이벤트가 따라가기를 꺼 버린다.
2. **E2E에서 20회 중 3회 실패했다.** 스트리밍 중 맨 위로 올렸는데 다시 바닥으로 끌려갔다. 원인은 경합이다.
   - `scroll` 이벤트는 다음 프레임에 발생한다.
   - 위로 올린 직후, 그 이벤트가 오기 전에 토큰이 도착했다.
   - 렌더 effect는 이전 판단(따라가기 켜짐)을 그대로 믿고 바닥으로 내렸다.

## 검토한 대안

1. 거리만 보고 판단 (처음 구현) — 위 두 문제가 남는다.
2. smooth 스크롤을 쓰지 않는다 — 1번 문제는 사라지지만 2번 경합은 남는다.
3. **"위로 움직였을 때만 끈다" + 렌더 effect(`useLayoutEffect`)에서 위치를 다시 확인한다**

## 결정

3번. `updateFollow(el)`을 `scroll` 이벤트와 `useLayoutEffect` 양쪽에서 호출한다.

- 바닥 근처면 켠다.
- `scrollTop`이 마지막으로 본 값보다 작아졌을 때(사용자가 위로 올림)만 끈다.
- 직접 스크롤한 뒤에는 마지막 값을 갱신한다.

## 결과

같은 E2E를 워커 4개로 반복했다.

- 수정 전: 20회 중 3회 실패. 실패할 때 `scrollTop`은 1546px, 1744px였다.
- 수정 후: 40회 모두 통과

측정 환경: 로컬 Windows, Chromium(Playwright 1.63), dev 서버

## 트레이드오프

- 내용이 줄어 브라우저가 `scrollTop`을 낮추는 경우도 "위로 움직임"으로 보인다. 이때는 바닥과의 거리가 0이라서 따라가기가 켜진 채로 유지된다.
- 사용자가 48px 안에서 조금 올리는 정도로는 따라가기가 꺼지지 않는다.
